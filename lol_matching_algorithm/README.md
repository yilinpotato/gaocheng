# LOL游戏匹配算法实现

## 项目概述

本项目实现了一个《英雄联盟》游戏的匹配算法，将五名担任不同位置的玩家组成一个团队。该算法采用C++实现，基于时间权重和分数范围动态调整的贪心策略，旨在优化玩家的等待时间和团队内部的分数平衡。

## 核心特性

- **完整的位置匹配**: 支持上单、打野、中单、射手、辅助五个位置的玩家匹配
- **智能优先级系统**: 基于等待时间的优先队列管理
- **动态分数范围**: 根据等待时间自动调整匹配的分数容忍度
- **贪心优化算法**: 综合考虑等待时间和分数差距的最优匹配
- **实时性能**: 高效的数据结构设计，支持大规模并发匹配
- **完整的统计信息**: 详细的匹配质量和性能分析

## 算法策略详解

### 1. 基于时间权重的优先匹配

算法优先处理等待时间最长的玩家，确保没有玩家长时间等待：

```cpp
// 优先级计算公式
priority = waitingTime * timeWeight - scoreDifferencePenalty
```

### 2. 分数范围动态调整机制

根据等待时间动态放宽分数匹配要求：

```cpp
// 动态分数范围计算
dynamicRange = baseRange * (1 + timeWeight * (waitTime / maxWaitTime))
```

**参数说明**:
- `baseRange`: 基础分数范围（默认200分）
- `timeWeight`: 时间权重因子（默认1.0）
- `maxWaitTime`: 最大等待时间阈值（默认300秒）

### 3. 贪心算法寻找最优组合

算法流程：
1. 选择等待时间最长的玩家作为基准
2. 计算该玩家的动态分数范围
3. 为其他四个位置选择最佳匹配玩家
4. 综合评估团队质量并确认匹配

## 复杂度分析

### 时间复杂度

- **添加玩家**: O(log n) - 优先队列插入
- **执行匹配**: O(n * k) - n为玩家数，k为位置数（常数5）
- **寻找最优团队**: O(n) - 贪心算法单次遍历

### 空间复杂度

- **存储复杂度**: O(n) - n为总玩家数
- **队列存储**: O(n) - 分布在5个位置队列中

### 性能优化

1. **懒删除策略**: 避免频繁重建优先队列
2. **智能指针**: 自动内存管理，减少内存泄漏风险
3. **位置分离**: 减少不必要的比较操作
4. **批量处理**: 一次匹配尽可能多的团队

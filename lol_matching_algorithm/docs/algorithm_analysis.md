# 算法设计与复杂度分析

## 1. 核心算法设计思路

### 1.1 问题抽象
LOL匹配问题可以抽象为一个多约束优化问题：
- **约束条件**：每个团队必须包含5个不同位置的玩家
- **优化目标**：
  1. 最小化平均排队等待时间
  2. 最小化团队内部成员间的平均分数差距

### 1.2 算法策略选择

经过分析，我们选择了**基于时间权重的贪心算法**，原因如下：

1. **时间复杂度优势**：相比于全局最优解算法（如匈牙利算法O(n³)），贪心算法在O(n)时间内就能找到近似最优解
2. **实时性要求**：游戏匹配需要快速响应，贪心算法能在毫秒级完成匹配
3. **实际效果**：在大多数情况下，贪心策略能够达到接近最优的匹配效果

## 2. 数据结构设计分析

### 2.1 优先队列的选择

```cpp
std::priority_queue<std::shared_ptr<Player>, 
                   std::vector<std::shared_ptr<Player>>,
                   CustomComparator> waitingQueue;
```

**设计原因**：
- **插入效率**：O(log n)，适合频繁加入玩家的场景
- **取最值效率**：O(1)，快速获取等待时间最长的玩家
- **内存局部性**：基于堆的实现有良好的缓存友好性

**替代方案比较**：
| 数据结构 | 插入 | 取最值 | 删除 | 内存占用 |
|---------|------|--------|------|----------|
| 优先队列 | O(log n) | O(1) | O(log n) | O(n) |
| 有序列表 | O(n) | O(1) | O(n) | O(n) |
| 哈希表 | O(1) | O(n) | O(1) | O(n) |

### 2.2 智能指针的使用

```cpp
std::vector<std::shared_ptr<Player>> players;
```

**优势**：
1. **自动内存管理**：避免内存泄漏
2. **共享所有权**：玩家对象可以在多个容器间安全共享
3. **异常安全**：RAII机制保证异常情况下的资源释放

## 3. 算法复杂度详细分析

### 3.1 时间复杂度

#### 添加玩家操作
```cpp
bool addPlayer(std::shared_ptr<Player> player)
```
- **复杂度**：O(log n)
- **分析**：主要开销在优先队列的插入操作
- **最坏情况**：所有玩家都选择同一位置，单个队列长度达到n

#### 执行匹配操作
```cpp
int performMatching()
```
- **复杂度**：O(m × k × log n)
  - m：可匹配的团队数量
  - k：位置数量（常数5）
  - log n：队列操作开销
- **实际复杂度**：O(n)，因为每个玩家最多被访问常数次

#### 寻找最优团队
```cpp
std::vector<std::shared_ptr<Player>> findOptimalTeam()
```
- **复杂度**：O(k × p)
  - k：位置数量（5）
  - p：每个位置的平均候选人数
- **优化**：通过动态分数范围减少候选人数量

### 3.2 空间复杂度

#### 存储复杂度
- **玩家存储**：O(n)，n为总玩家数
- **队列存储**：O(n)，分布在5个位置队列中
- **团队存储**：O(t)，t为已匹配团队数

#### 临时空间
- **匹配过程**：O(k)，存储候选团队成员
- **统计信息**：O(1)，固定大小的计数器

## 4. 算法优化策略

### 4.1 动态分数范围调整

```cpp
int getDynamicScoreRange(double waitingTime) const {
    double multiplier = 1.0 + timeWeight * (waitingTime / maxWaitTime);
    return static_cast<int>(baseScoreRange * multiplier);
}
```

**数学模型**：
- 基础公式：`range(t) = baseRange × (1 + α × (t / T_max))`
- 参数说明：
  - `α`：时间权重系数
  - `t`：当前等待时间
  - `T_max`：最大容忍等待时间

**效果分析**：
- 等待时间短：严格的分数匹配，保证游戏质量
- 等待时间长：放宽分数要求，优先减少等待时间

### 4.2 懒删除策略

传统删除方式需要O(n)时间重建堆，懒删除通过标记避免这一开销：

```cpp
void removeMatchedPlayers(const std::vector<std::shared_ptr<Player>>& players) {
    for (const auto& player : players) {
        player->setIsMatched(true);  // 标记为已匹配
    }
    // 懒删除：在下次访问时跳过已匹配玩家
}
```

**优势**：
- 删除操作：O(1) → O(k)，k为团队大小（常数5）
- 减少堆重建开销
- 保持队列结构稳定

### 4.3 贪心选择策略

算法采用多级贪心策略：

1. **第一级**：选择等待时间最长的玩家作为基准
2. **第二级**：在分数范围内选择等待时间最长的其他位置玩家
3. **第三级**：综合考虑分数差距和等待时间的加权评分

```cpp
double score = waitingTime * 2.0 - abs(scoreDiff) * 0.1;
```

## 7. 理论基础

### 7.1 图论模型
匹配问题可以建模为二分图匹配：
- 左侧节点：等待匹配的玩家
- 右侧节点：可用的团队位置
- 边权重：匹配质量评分

### 7.2 优化理论
采用多目标优化框架：
```
minimize: α × waiting_time + β × score_variance
subject to: team_size = 5, unique_positions = 5
```

### 7.3 概率分析
假设玩家位置选择服从均匀分布，理论匹配成功率为：
```
P(success) = (n/5)^5 / n^5 × C(n,5) / 5^5
```

这一理论分析为算法参数调优提供了重要依据。
